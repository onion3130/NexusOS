# NexusOS v1.6.0

NexusOS v1.6.0 is the stable streaming Assistant release. It makes ordinary NVIDIA NIM and OpenAI-compatible conversations feel responsive on the Raspberry Pi while preserving the existing buffered tool and confirmation workflows.

## Highlights

- **Streaming Assistant:** added authenticated Server-Sent Events at `POST /api/v1/conversations/{conversation_id}/messages/stream`.
- **NVIDIA NIM support:** hosted OpenAI-compatible streaming responses work through the existing provider-neutral gateway.
- **Incremental UI:** ordinary conversational prompts render text deltas as they arrive in the Assistant workspace.
- **Tool safety preserved:** task actions, system lookups, notes tools, maintenance actions, and other tool-intent prompts continue through the existing buffered path with permissions and confirmation requirements.
- **Grounded responses:** streaming can include the existing bounded note/source grounding and persists final server-derived provenance.
- **No migration:** the release adds no database migration and no new runtime dependency.

## Security and reliability

- The stream is authenticated, ownership-scoped, CSRF-protected for cookie-authenticated browser mutations, and bounded by output size and an absolute provider deadline.
- The streaming endpoint requires a user-scoped idempotency key; an identical retry replays the completed response instead of creating duplicate messages, and a stale reservation is lease-recovered without duplicating the persisted user input. Reusing a key with different content is rejected.
- Provider keys remain server-side and are never sent to the browser or stored in stream events.
- Streaming is text-only; it cannot execute tools, approve actions, mutate tasks, or control the host.
- Partial or failed browser streams reconcile with the persisted conversation state rather than treating uncommitted text as durable history.
- Source content remains explicitly untrusted context and cannot authorize tools or override policy.

## Upgrade

Preserve the existing `.env` and data volume, then update the API and web services:

```sh
git fetch --tags origin
git checkout v1.6.0
docker compose --env-file .env run --rm nexus-api python -m alembic upgrade head
docker compose --env-file .env up --build -d
```

The migration head remains `0019_source_sync`; no schema change is required for this release.

## Raspberry Pi 5 and Docker

The feature uses the existing Python, httpx/httpcore, FastAPI, Next.js, and ARM64-compatible images. It does not load a model on the Pi; hosted NIM remains an optional outbound provider. Use an external SSD for `DATA_DIR`, keep exactly one worker, and validate proxy buffering, timeout behavior, memory use, and long responses on the target Pi. Docker and target ARM64 runtime streaming validation are required operator checks when Docker is unavailable locally.
