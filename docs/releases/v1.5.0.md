# NexusOS v1.5.0

NexusOS v1.5.0 is the stable external source ingestion and approved-root synchronization release. It adds a private, bounded path for bringing UTF-8 text and Markdown reference material into NexusOS and keeping approved local files current for source-aware retrieval and grounded Assistant responses.

## Highlights

- **External sources:** upload UTF-8 text and Markdown files through the authenticated Sources workspace.
- **Approved-file imports:** discover and import eligible files from server-configured `WORKSPACE_ROOTS` without accepting browser-controlled filesystem paths.
- **Versioned ingestion:** create immutable source versions, deterministic chunks, SHA-256 metadata, lifecycle states, and durable background ingestion jobs.
- **Approved-root synchronization:** opt in per imported source, poll on bounded 15-minute-to-24-hour intervals, detect changes safely, re-ingest new versions, retry failures, and manually sync from the Sources workspace.
- **Grounded Assistant context:** retrieve current source chunks with user-scoped provenance while keeping source text explicitly untrusted.
- **NVIDIA model catalog:** browse hosted NVIDIA-compatible chat and embedding model presets from the owner Admin console, with offline fallback presets.
- **Admin console:** manage AI setup, system status, operations, backups, and deployment details in a dedicated owner-only layout.
- **System health UX:** classify Pi telemetry and service health as healthy, warning, or critical with bounded refresh behavior.
- **Web updates:** queue a fixed, audited host update request for the operator-installed Pi update agent; the API never executes arbitrary host commands.

## Security and privacy

- All source operations are authenticated, permission-checked, ownership-scoped, CSRF-protected for browser mutations, idempotent where applicable, and audited.
- Synchronization accepts only opaque server-resolved approved-root file identifiers; client paths, arbitrary URLs, crawling, shell commands, and dynamic destinations are not accepted.
- Uploaded bytes remain beneath the server-owned data directory with generated storage names; source metadata and API responses are bounded and redacted.
- Provider credentials stay server-side or in the encrypted runtime configuration; they are never returned to the browser, stored in SQLite, or written to logs.
- PDF/OCR parsing, arbitrary URL ingestion, web crawling, autonomous memory extraction, and model-written notes remain intentionally out of scope.

## Upgrade

Preserve the existing `.env` and data volume, then run the migration before restarting the stack:

```sh
git fetch --tags origin
git checkout v1.5.0
docker compose --env-file .env run --rm nexus-api python -m alembic upgrade head
docker compose --env-file .env up --build -d
```

For a local installation:

```sh
cd apps/api
python -m alembic upgrade head
```

The migration head is `0019_source_sync`. Existing source data is preserved; the synchronization policy migration adds optional metadata only and does not enable synchronization automatically.

## Raspberry Pi 5 and Docker

The API, web, and worker remain ARM64-compatible non-root services. Synchronization runs in the existing bounded worker and reads only server-configured approved roots. Use an external SSD for `DATA_DIR` and run exactly one worker in the deployment topology. Docker image builds, hardened proxy startup, systemd boot, and sustained ingestion should be validated on the target Raspberry Pi 5 or another Docker-enabled ARM64 host.

## Validation

- Backend tests and migration coverage: run `cd apps/api && python -m pytest`.
- Frontend validation: run `cd apps/web && npm run typecheck && npm run build`.
- Python compilation and whitespace checks: run `python -m py_compile ...` and `git diff --check`.
- Docker Compose and ARM64 runtime validation require a Docker-enabled host; the current development environment may not provide Docker.
