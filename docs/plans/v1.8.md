# NexusOS v1.8 — Richer Retrieval & Source Expansion (plan)

**Status:** pending owner approval
**Version target:** v1.8.0
**Migration heads:** `0021_source_retrieval`, `0022_source_refresh_crawl` (from `0020`)
**Last updated:** 2026-08-06

## Goal

Make retrieval genuinely cross-entity (notes + every ingested source, in all three modes) and expand what counts as a source: bounded multi-page web crawling, RSS/Atom feeds with scheduled refresh, and EPUB/DOCX parsing. Everything stays worker-only, SSRF-safe, and pure-Python/ARM64-safe. OCR, JavaScript rendering, arbitrary protocols, and autonomous memory remain explicitly deferred.

## Architecture

Three additive layers over the existing pipeline:

- **kind=url** → fetch → `html-text` → existing ingestion (versions → deterministic chunks)
- **kind=rss** → fetch → `rss-text` (new) → ingestion, driven by `source_refresh_configs` (scheduled re-fetch)
- **kind=crawl** → bounded same-host BFS fetch → `html-text` per page → one source (persisted crawl state, resumable)
- **upload** → `epub-text` / `docx-text` (new stdlib parsers)
- **retrieval** → `source_chunks_fts` (chunk-level FTS5) + `source_chunk_embeddings` (provider-neutral vectors) → unified `/search/retrieve` (filters) → grounding, Search UI, and a new `sources.search` assistant tool

New shared `app/core/net.py` extracts the duplicated pinned-address, DNS-rebinding-resistant transport currently copied in the assistant gateway, embeddings gateway, sources fetch, and `nim_setup`.

## Database changes (reversible migrations)

### `0021_source_retrieval`

- `source_chunk_documents` + `source_chunks_fts` (FTS5): per-chunk projection (content, source_id, kind, source_version, updated_at) mirroring the notes FTS pattern, maintained transactionally during ingestion.
- `source_chunk_embeddings`: mirrors `note_chunk_embeddings` (provider, model, dimensions, vector_json, content_hash, source_version, status/attempts/lock/available_at) with a composite claim-scan index.

### `0022_source_refresh_crawl`

- `source_refresh_configs` (source_id FK, enabled, interval_seconds, last_checked/success, last_error_code, next_check_at, cursor token) — generalizes scheduled refresh beyond approved files to `url`/`rss` kinds.
- `sources.crawl_state_json` + `sources.crawl_max_pages` (nullable) for resumable bounded crawls (normalized visited URLs, page count).
- `SourceKind` extended to `"rss"` and `"crawl"` (string column; schema literals updated, no column change).

## API endpoints

- `GET /api/v1/search/retrieve` — add `kind=all|note|external_source`, `source_id` (search within one source), `tag` filters; semantic/hybrid now include source chunks when permitted.
- `GET /api/v1/sources/{id}/search?q=&limit=` — chunk-level FTS scoped to one source.
- `GET /api/v1/search/embeddings/status` — extend to report source-chunk pending/ready/failed counts.
- `POST /api/v1/sources/rss` `{url, title?, interval_seconds?}` — creates `kind=rss` + enabled refresh config; first fetch worker-only.
- `POST /api/v1/sources/crawl` `{url, title?, max_pages?}` — creates `kind=crawl`; worker runs the bounded crawl then ingests.
- `POST/DELETE /api/v1/sources/{id}/refresh` and `POST /{id}/refresh-now` — scheduled/manual re-fetch for `url`/`rss` (mirrors approved-file sync routes; `sync` stays file-scoped).

## Frontend components

- **Search workspace:** source result cards (kind badge, source title, excerpt, "open source" → Sources), kind + source filter chips, embedding-status line including sources.
- **Sources workspace:** "Add RSS feed" and "Crawl website" forms; refresh interval UI for url/rss; per-source search box showing matched chunks; crawl/rss status and error codes in existing lifecycle states.
- **API client** (`lib/sources.ts`, `lib/notes.ts`): rss/crawl/refresh/within-source search functions; typed result unions.

## AI architecture

- **Grounding:** semantic and hybrid modes include external source chunks (gated by `sources.read`; semantic-over-sources gated by new `sources.semantic` permission added to owner+member with idempotent role refresh). Provenance extends with source `kind`; the untrusted-context boundary is unchanged.
- **Assistant tools:** new read-only `sources.search` (lexical/semantic/hybrid over sources, bounded) and `sources.read` (bounded excerpt of one source's current version). No autonomous source selection.
- **Hybrid scoring** extended to sources: blend normalized lexical + semantic per source chunk (same 0.45/0.55 merge), replacing the current lexical-only source path.

## Search indexing strategy

- Source chunk **FTS5** maintained in the ingestion transaction (content_hash-driven, like notes `_sync_search_document`), bm25 weights matched to notes, ownership-scoped via `source_chunks.user_id`.
- **Embeddings:** a second worker claim/process pass over `source_chunk_embeddings` reusing the same gateway, provider/model/dimension caps, stale detection, retries, and lexical fallback; deterministic `content_hash` drives staleness.
- Bounds reuse `embedding_max_chunk_length`, `embedding_max_dimensions`, `embedding_batch_size`.

## Security considerations

- RSS and crawl **reuse the pinned SSRF-safe transport**: HTTPS-only, per-hop redirect re-validation, private/loopback/metadata rejection, 30 s timeout, 10 MB cap, content-type allowlists (RSS adds xml/rss/atom).
- Crawl is **same-host confined** (every hop must stay on the base scheme+host), capped pages (default 25, hard cap 50), sequential fetches, normalized-URL dedup, persisted state for resume; page text never rendered/executed.
- RSS parse bounds (≤ 50 items, bounded title/link/description); entry links are **not** recursively fetched in v1.8 (documented).
- New parsers (EPUB/DOCX) are zip/XML readers with 2 MB extracted-text caps and stable error codes; content remains untrusted reference material.
- New permissions (`sources.semantic`) only grant retrieval, never write; all new mutations keep CSRF + ownership + audit.

## Raspberry Pi 5 considerations

Everything is pure Python (stdlib zip/XML, existing pypdf/html parsers, SQLite FTS5, bounded provider-neutral embeddings). Crawl caps sequential fetch pressure; FTS/embedding writes are per-batch; RSS refresh defaults to hourly. No native toolchain additions.
