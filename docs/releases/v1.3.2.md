# NexusOS v1.3.2

NexusOS v1.3.2 fixes the ARM64 Docker web-container healthcheck binding while preserving the v1.3 NVIDIA NIM and v1.3.1 migration compatibility work.

## Fix

- Set `HOSTNAME=0.0.0.0` in the standalone Next.js web image so the server listens on the container network interface and loopback.
- The previous image served successfully through the published host port but listened only on the container hostname, causing the container-local healthcheck to report unhealthy.
- No database migration or data reset is required for this patch.

## Validation

- Backend suite: passed — 139 tests.
- Python compilation: passed.
- Frontend TypeScript typecheck: passed.
- Frontend production build: passed.
- Pi API readiness: passed at migration head `0016_embeddings`.
- Pi LAN web HTTP: passed.
- Previous web healthcheck root cause reproduced inside the container.

## Upgrade

```sh
git fetch --tags origin
git checkout v1.3.2
# Preserve the existing .env and data volume.
docker compose --env-file .env build nexus-web
docker compose --env-file .env up -d --force-recreate nexus-web
```

After startup, verify:

```sh
docker compose --env-file .env ps
curl http://127.0.0.1:3000
```

Hosted NVIDIA NIM remains opt-in. The deployed Pi currently uses `AI_PROVIDER=disabled` and has no NVIDIA API key configured.
