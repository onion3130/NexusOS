# NexusOS v1.3.0

NexusOS v1.3.0 adds first-class NVIDIA NIM configuration to the existing provider-neutral assistant and semantic-retrieval gateways.

## Highlights

- Hosted NVIDIA API Catalog defaults for chat completions and embeddings.
- `NVIDIA_API_KEY` server-side credential fallback for both chat and embeddings.
- Explicit model configuration through `AI_MODEL` and `EMBEDDING_MODEL`.
- Optional reviewed custom endpoints for compatible public providers.
- Existing OpenAI-compatible providers remain backward-compatible.
- Provider keys remain outside the browser, web container, database, audit records, and logs.
- Existing timeout, response-size, output-size, target validation, DNS-rebinding-resistant transport, and lexical fallback protections remain active.

## Configuration

For hosted NVIDIA API Catalog chat:

```dotenv
AI_PROVIDER=nvidia_nim
AI_MODEL=meta/llama-3.1-8b-instruct
NVIDIA_API_KEY=replace-with-your-server-side-key
```

For hosted NIM embeddings:

```dotenv
EMBEDDING_PROVIDER=nvidia_nim
EMBEDDING_MODEL=nvidia/nv-embed-v1
NVIDIA_API_KEY=replace-with-your-server-side-key
```

The hosted endpoints default to:

- `https://integrate.api.nvidia.com/v1/chat/completions`
- `https://integrate.api.nvidia.com/v1/embeddings`

Set `AI_BASE_URL` or `EMBEDDING_BASE_URL` explicitly only when using a reviewed compatible public endpoint. Keep `AI_PROVIDER=disabled` and `EMBEDDING_PROVIDER=disabled` when NIM is not required.

## Raspberry Pi 5 deployment

The API and worker remain ARM64-compatible, non-root, and use the existing SQLite/SSD architecture. Hosted NIM performs inference remotely, so no NVIDIA GPU or NIM container is installed on the Pi. The Pi requires outbound HTTPS access to the NVIDIA API Catalog when hosted NIM is enabled. The NIM key belongs in the Pi's private `.env` only.

## Security notes

NIM is opt-in. The application never accepts a provider URL or credential from a browser or model output. Custom endpoint URLs remain subject to absolute HTTP(S), credential-free URL, public-target, timeout, and bounded-response validation. Retrieved note text remains untrusted source material and cannot grant tool permissions or bypass confirmation workflows.

## Upgrade

```sh
git fetch --tags origin
git checkout v1.3.0
cp .env.example .env
# Set a strong JWT_SECRET and configure NIM only if needed.
python scripts/validate_env.py --env-file .env
docker compose --env-file .env run --rm nexus-api python -m alembic upgrade head
docker compose --env-file .env up --build -d
```
