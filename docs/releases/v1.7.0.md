# NexusOS v1.7.0

NexusOS v1.7.0 is the richer document parsing and source expansion release. It adds bounded **PDF parsing** and **single-page HTTPS URL ingestion** so more of your private reference material can feed source-aware retrieval and grounded Assistant responses — with the same generated-name storage, immutable versions, deterministic chunks, and worker-only processing as text and Markdown sources.

## Highlights

- **PDF sources:** upload bounded PDFs (≤ 10 MB) through the existing Sources upload form. The worker parses them with pure-Python `pypdf` (no native ARM64 toolchain), capped at 200 pages and 2 MB of extracted text; encrypted, malformed, and oversized documents fail with stable error codes.
- **URL sources:** add a single-page HTTPS URL from the Sources workspace. The API creates an inert source record and a worker `source_fetch` job; the fetch runs only in the worker using the same pinned-address, DNS-rebinding-resistant transport as the assistant and embedding gateways.
- **HTML sources:** fetched HTML is normalized to plain text with the standard library (scripts, styles, iframes, and SVG skipped) and never rendered or executed.
- **Same pipeline:** fetched bytes are stored under a server-generated name and handed to the existing ingestion pipeline unchanged, so versioning, chunking, retrieval, lifecycle, and grounding behavior stay identical.
- **Migration `0020_source_expansion`:** adds a nullable `sources.source_url` column for URL sources; fully reversible.
- **New runtime dependency:** `pypdf>=5,<7` (pure Python, ARM64-compatible).

## Security and reliability

- URL fetching is worker-only: the browser never performs the network request.
- Targets are validated for scheme (**HTTPS only**), hostname, and credentials at request time, then re-validated on **every redirect hop** (max 3) before any bytes are read.
- Private, loopback, link-local, multicast, reserved, and metadata hosts are rejected, and DNS is resolved once to a pinned public address so a hostname cannot be re-resolved to an internal address after validation.
- Fetching is bounded by a 30-second timeout, a 10 MB response cap enforced during streaming, and a content-type allowlist (HTML, XHTML, Markdown, text, PDF).
- PDF/HTML parsing runs only in the worker with hard page/text bounds that protect the Raspberry Pi memory budget.
- Plaintext HTTP is rejected so fetched content cannot be altered or observed by a network intermediary.
- Source content remains untrusted reference material: it cannot authorize tools, permissions, host actions, or policy changes.
- All uploads, fetches, parses, and failures are ownership-scoped, audited, and surfaced as redacted error codes.

## Upgrade

Preserve the existing `.env` and data volume, then update the API and web services:

```sh
git fetch --tags origin
git checkout v1.7.0
docker compose --env-file .env run --rm nexus-api python -m alembic upgrade head
docker compose --env-file .env up --build -d
```

The migration head is now `0020_source_expansion`.

## Raspberry Pi 5 and Docker

The new parser is pure Python and the URL fetch reuses the existing httpx/httpcore stack, so no native ARM64 toolchain is required. PDF extraction runs only in the worker with page/text bounds. Keep exactly one worker, use an external SSD for `DATA_DIR`, and validate sustained fetch/parse behavior, memory use, and timeout behavior on the target Pi. Docker and target ARM64 runtime validation are required operator checks when Docker is unavailable locally.
